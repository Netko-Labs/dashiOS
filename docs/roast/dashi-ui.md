# Components and @dashi/ui

**The roast**

- The Components app is pinned second in the Dock (`packages/shell/src/apps.ts:65-77`) and shows 239 kebab-case shadcn examples from `@mirinjs/metal-ui`. No first-party app imports that library: a grep of `packages/shell` and `packages/greeter` finds no code import of it, while 160 files import `@dashi/ui`. And `@dashi/ui`, the library every app is actually built from, has no examples in it at all.
- On a light desktop it opens in dark mode (`components.png`), because metal-ui's provider says "system resolves to dark on Metal" (`mirin/packages/mirin-metal-ui/src/provider.tsx:8,25`). So the one app about consistency is the first one to break it.
- `@dashi/ui` has a Button but no Switch. The Switch lives in the Wi-Fi folder (`packages/shell/src/wifi/switch.tsx`), and Settings reaches over and borrows it from there (`settings-app/panes/mouse.tsx:3`).
- Count the copies: three checkboxes, three month grids, three "Open With" lists, two search fields, two sliders, and four sidebar-row heights. In practice the design system is a list of suggestions.
- Keyboard support is a hidden 1×1 text field standing in for a keyboard (`key-sink.tsx:21-45`). It knows Up and Down but not Left, Right or Tab. Metal has had a real `onKeyDown`, with modifiers, all along (`mirin/packages/mirin-metal/src/types.ts:168-177,268`).
- The secondary button is 7% ink with no border on a near-white window: 1.14:1. You find Cancel by reading the labels.

**Improvements**

1. **Recommended.** *Make Components the `@dashi/ui` gallery.* Rebuild it on `AppWindow` and `SidebarItem` with one page per component, showing every state (rest, hover, pressed, focused, disabled, selected, danger) in light and dark side by side. Add a measurements overlay like the one in `design.html`, and keep metal-ui as a second section. It should follow Dark Mode through `followDarkMode`. Unpin it from the default Dock and list it in the launcher as a developer tool. *Why:* the gallery should show what apps are built from, and the gaps in findings 5 and 12 only become visible once they sit next to each other. *Size:* M.
2. **Recommended.** *Real keyboard and focus in `@dashi/ui`.* Rebuild `KeySink` on `onKeyDown`, then add a focus model: Tab and Shift+Tab order, roving focus inside groups (Choices, Segmented, sidebar, table, menu), Space/Enter to activate, and a 2 px kombu ring shown only for keyboard focus. *Why:* today a keyboard user can't press a single button, and the Metal API that fixes it already exists. *Size:* L.
3. **Recommended.** *Fill the control gaps, then delete the copies.* Add Switch, Slider, Checkbox and Radio, PopUpButton (select), Stepper/number field, ProgressBar and Spinner, Tabs, Tooltip, a link or disclosure button, ToolbarDivider, `ToolbarButton on`, Segmented with glyph segments, `Button size="small"` with a glyph, MonthGrid, an app-list "Open With" sheet, and an `AlertWindow` frame for portal and dialog windows. *Why:* finding 5 lists about 20 local re-implementations that already disagree in size and color. *Size:* L.
4. **Recommended.** *Bring the palette in line with the brand and AA contrast.* Add `ume`, `broth` and `moss` tokens and retire `critical` and `batteryLow` as separate reds. Add a darker accent fill for white text (it needs to reach 4.5:1; tune it and check in the gallery). Raise light-mode `textMuted` to about 65%. Give secondary buttons, the off-switch track and checkboxes a 3:1 edge. *Why:* findings 6 and 8. One color, one job only works if the jobs have tokens. *Size:* S.
5. **Recommended.** *Remove `subtitle` from `AppWindow`* and update `design.html`. Counts and scopes move to the sidebar badge or the content's own header. *Why:* it is a library-level violation of the one-chrome-row rule, copied by five apps. *Size:* S.
6. *Accessibility tree in mirin-metal* (AccessKit to AT-SPI), and make `label` required on glyph-only controls so the names exist before the tree does. *Why:* finding 1. *Size:* L.
7. *PopupMenu v2:* separators and sections, arrow keys, type-to-select, clamping and flipping inside the window, submenus, and the `xl` shadow from the doc. *Why:* finding 9. Every app's context menu is affected. *Size:* M.
8. *A lint for design tokens:* no hex literals, raw `fontSize` or raw `borderRadius` outside `packages/dashi-ui`. Expose `type.*`, `radius.*`, `height.*` and `shadow.*` constants. *Why:* finding 12 will keep growing without a rule a machine can check. *Size:* M.
9. *Settle metal-ui vs `@dashi/ui`.* Either ship a Dashi theme for metal-ui and migrate (`tasks/todo.md:386-390`), or rewrite `docs/conventions.md` "UI Components" to match what the code does. *Why:* the convention says "use metal-ui for anything shadcn has", and no app does. *Size:* S to decide, L to migrate.
10. *Quick fixes for Components:* search by component name, arrow-key navigation, Esc to clear, sentence-case names ("Alert dialog"), the preview top-aligned, a Segmented "Light / Dark / Both" in place of the mislabeled button, and a View menu that carries it. *Why:* finding 14. *Size:* S.

**One big idea**

Make the Components app a live spec. The values in `design.html` are generated from `@dashi/ui`'s tokens. The gallery renders every component in every state in both modes, with contrast and measurements drawn on. CI screenshots each exhibit in the VM (`vm/agent screenshot`) and diffs it. Then make it a rule that a control must exist in the gallery before an app may use it. That way the design system can be checked, instead of living as a description in a doc.

**Cross-app notes (proposed design-guideline rules)**

1. **One chrome row.** A window has one toolbar row with a one-line title. Counts, scopes and folder names go in the sidebar badge or the content, never under the title. `AppWindow` has no `subtitle`.
2. **Two users means it moves to `@dashi/ui`.** If a second app needs a control, it moves into `@dashi/ui` before the second copy ships. A `View` with `onPress` and `hoverBackgroundColor` outside `packages/dashi-ui` gets flagged in review.
3. **Everything works from the keyboard.** Every control is reachable with Tab, activates with Space or Enter, and moves with the arrows inside a group (pills, segments, sidebar, table, menu). Esc closes the topmost thing. Focus shows as a 2 px kombu ring, 2 px out, only after keyboard input.
4. **Contrast.** Text, muted text included, is at least 4.5:1 at 13 px and below. Control edges (buttons, fields, checkboxes, off switches) are at least 3:1 against their ground. Check both modes in the gallery before merging.
5. **One color, one job, as tokens.** Kombu: selected, on, primary. Ume: destroy, error, close. Broth: warning, set aside. Moss: success. Shiso: agents only. Icons are ink or muted, never kombu, unless they are selected. Decorative tints come from one shared list that leaves out the job colors.
6. **Tokens only.** No hex in apps. Grounds come from `Surface`, inks from `Palette`. A new need adds a token to `palette.ts` and `design.html` in the same commit.
7. **Type scale.** 11 caption and section heading, 12 secondary, 13 body and labels, 15 empty-state title, 20 page title. Weights are 400, 600 and 700 only. No fractional sizes.
8. **Radii nest.** Window 12, group and card 10, sheet 12, control 7, menu row and small control 5, checkbox 4, pills height ÷ 2. Nothing else.
9. **Heights.** Control 28 (small 24). Sidebar row 32, or 28 when compact. Table row 24. List row 30. Settings row at least 44. Toolbar 38.
10. **Two shadows:** `sm` for raised controls and cards, `xl` for sheets and menus. The doc and the code agree, or the doc changes.
11. **Picking one of N.** For 2–4 short options, use Segmented. For 2–6 options in a settings row, use Choices pills. Anything longer or of unknown length (printers, filters, apps, languages) uses a PopUpButton or a list.
12. **Buttons say what they do,** in sentence case ("Save as PDF…", "Don’t save"), with Title Case only in the menu bar (`docs/brand.html`). Use curly apostrophes and the ellipsis character. Never show a MIME type, app id or path where a name exists.
13. **Glyph-only buttons need a name:** `label` is required, shown as a tooltip and used as the accessible name.
14. **Every window follows the shell's Dark Mode from the first frame.** No app-level theme switch, the gallery included; it shows both modes side by side.
15. **Disabled means the whole control at about 40% opacity.** A disabled primary button still reads as primary.
16. **Menus stay inside the window** (clamped or flipped), group items with separators, and every context-menu command also exists in a menu-bar menu.
17. **Pressed feedback.** Every pressable control gets a pressed state (draw it through `onPointer` down/up until Metal has one). Hover alone is not feedback.
