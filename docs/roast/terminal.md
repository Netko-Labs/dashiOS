# Terminal

**The roast**

- The first thing you see is a prompt you can't read. In `terminal.png` the `~` is about #C1C880 on pure white, around 1.7:1 contrast. The welcome message is "get closer to the screen".
- It runs on Ghostty's engine and then draws every row as a stack of proportional `<Text>` runs, with the cursor placed on a separate pixel grid. One emoji is enough to pull the text and the cursor apart.
- `Line` is wrapped in `memo`, and then gets a brand-new `look` object on every frame. That's a "Do Not Disturb" sign hung on a revolving door.
- The menu says ⇧❖W is "Close Window". The keymap disagrees, so it only closes a tab. On the other hand, ❖W on your last tab ends your `ssh` session without asking.
- Tabs get a second 28 px bar under a 28 px title bar. On Dashi, where vertical space is sacred, that's two rows of chrome to say "Terminal" twice.
- The bell rings, dashi-term sends it, and the app throws it away. The terminal is calm by default, and also by deafness.

**Improvements**

1. **Recommended.** *What:* Ship a Dashi terminal palette, a light and a dark set of 16 ANSI colors with ground, ink, cursor and selection, defined in `palette.ts`. Pass it to libghostty so programs' colors resolve to it, and honor the engine's `fg`/`bg` for OSC 10/11. *Why:* Today the first screen fails contrast (#1). Every CLI's colors are design decisions Dashi isn't making. *Size:* M.
2. **Recommended.** *What:* Make the render path cheap. Memoize `look` and hoist `systemClipboard()` to `main.tsx`. Keep each tab's screen in a small store outside the window's React state, so a frame re-renders only the changed `Line`s, not the tab bar and menus. Publish menus only when titles change. *Why:* `cat` of a big log re-renders every row 125 times a second today (#3). *Size:* S.
3. **Recommended.** *What:* Draw on the grid. Either give each span a fixed width of `cols × cell.width` and position runs by column, or add a mirin cell-grid primitive that lays out glyphs at fixed advances and clips wide ones. Use the same grid for the cursor, selection and hit-testing. *Why:* It fixes the cursor drifting away from the text after emoji, CJK or icons (#2). This is the thing that makes a terminal feel broken. *Size:* M (L with a mirin primitive).
4. **Recommended.** *What:* Make closing safe and correct. dashi-term reports whether the PTY's foreground process group is the shell (`tcgetpgrp`). If it isn't, closing a tab or window shows a sheet: "Close this tab? “ssh dashi@vm” is still running." Fix ⇧❖W by giving the `super+shift+w` chord its own rule, or by passing Shift through in `close-window`, and add the `reservedBy` check to the Terminal's menu test. *Why:* Losing a session to ❖W is the most expensive mistake in a terminal (#4, #5). *Size:* S/M.
5. **Recommended.** *What:* Put the tabs in the title bar. With two or more tabs, the standard bar's title becomes the tab strip, so it stays one row. Show the grid size only while the window is resizing, for about one second. *Why:* It follows the owner's one-chrome-row rule (#6). The size suffix is noise 99% of the time (#10). *Size:* M (needs the compositor to let the app draw into the standard bar, or a unified toolbar holding only tabs).
6. *What:* Find in scrollback. ❖F opens a compact search field in the title row, ❖G and ⇧❖G step through matches, and matches are highlighted in the grid through libghostty's search. *Why:* It's a missing day-one basic (#8). *Size:* M.
7. *What:* Mouse reporting and alternate-screen wheel. When a program enables mouse modes, encode presses, drags and the wheel for it (libghostty has the encoder), and hold ⇧ to select anyway. In the alternate screen without mouse mode, send the wheel as arrow keys. *Why:* vim, less, htop and tmux are dead to the mouse today (#7). *Size:* M.
8. *What:* Scrollback affordances. Draw a thin overlay scroll bar from `scroll` with the mirin fade timing. Add a "jump to bottom" pill when scrolled up. Make ⇧PgUp/⇧PgDn and ❖↑/❖↓ scroll locally (add terminal rules before `keymap.ts:140`). Drop the ×3 on the wheel. *Size:* S.
9. *What:* Bell. A gentle flash of the grid's edge and, when the window isn't focused, the menu-bar or Dock attention dot that design.html already defines ("Attention is a 6 px dot… never a flash"). *Why:* #12. *Size:* S.
10. *What:* Preferences: View → Bigger/Smaller/Actual Size (❖=, ❖−, ❖0) that re-measures the cell, plus one Settings pane for font, size, cursor style and blink, and the palette. Profiles can come later. *Why:* #11. *Size:* M.
11. *What:* Links. Detect URLs and file paths, support OSC 8, and underline on hover. Open with ❖-click once mirin's `PointerInfo` reports modifiers. *Why:* #13. *Size:* M.
12. *What:* Error states. When the engine's stdout ends without `exit`, or the shell can't start, show an in-window message ("The shell stopped unexpectedly. Press Return to start a new one.") and keep the window. Show a sheet for a missing dashi-term instead of a silent exit. *Why:* #15. *Size:* S.
13. *What:* Split panes. ❖D splits, ⇧❖D splits horizontally, and ⌥❖ plus arrows moves between panes. Each pane is a dashi-term, the way tabs already are. *Why:* #16. Every modern terminal has them, and Dashi's tiling story invites them. *Size:* L.
14. *What:* Cursor polish. Invert the glyph under a block cursor (draw the cell's char in the ground color on top), go hollow when unfocused, and blink as the program asks, honoring Reduce Motion. *Why:* #17. *Size:* S.

**One big idea**

Make Dashi's Terminal the one that knows where commands begin and end. Ship shell integration on by default in Dashi's zsh config: OSC 7 for the current folder, OSC 133 prompt and command marks, and the title. Then build on it:

- Tabs are named by folder and running command.
- New tabs open where you are.
- ❖↑ and ❖↓ jump between prompts.
- Clicking a command selects its output for ❖C.
- A command that failed gets a small ume mark in the left margin.
- A long command that finishes while the window is in the background posts a notification.

All of it is calm, all of it is Dashi's, and each piece makes the scrollback feel organized instead of being a wall of text.

**Cross-app notes**

- **Terminal palette is a design-system token.** Dashi has no ANSI palette in `packages/dashi-ui/src/theme/palette.ts`. It should have one, light and dark, and `appearance/gtk-css.ts` and foot/kitty configs could use the same values so every terminal on Dashi matches.
- **Hard-coded grounds.** Terminal paints #ffffff/#1c1c1e and #ececee/#141416 itself (`view.tsx:37-38`, `view.tsx:202`). Content surfaces should come from `useSurface()`, plus a `surface.console` token if a terminal needs its own.
- **The keymap's Shift rule eats ⇧❖ chords.** A rule that doesn't name Shift also takes the Shift variant (`keymap.ts:9`), and `shortcuts.ts:119-122` replays it as the unshifted chord. So any app's ⇧❖W, ⇧❖H or ⇧❖M row is silently broken. Every app's menu test should run `reservedBy` (only the Editor's does).
- **mirin `PointerInfo` has no button and no modifiers** (`types.ts:160-166`). That blocks right-click menus, middle-click paste, ⇧-click to extend, and ❖-click links in every Dashi app, not only Terminal.
- **Clipboard through `wl-copy`** flashes an app in the Dock on every copy (`tasks/todo.md:365`). A mirin clipboard API is a platform fix, not an app one.
- **Second bars.** Terminal's tab bar is a second chrome row. The guidelines should spell out where tabs go under "one chrome row": in the title bar or unified toolbar, never under it.
- **Title-bar text.** design.html's Terminal example ("dashi@dashi:~ — 96×26") doesn't match what ships ("Terminal — 96×26"). Either ship the title integration or fix the doc.
- **Ctrl+arrows are taken globally** for Spaces and Overview (`keymap.ts:83-88`). Terminal users who rely on them (tmux, vim, readline word motion) never get them. The guidelines should decide whether terminals keep Ctrl+arrows or whether Dashi documents ⌥ as the replacement.
