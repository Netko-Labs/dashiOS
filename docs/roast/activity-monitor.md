# Activity Monitor

**The roast**

- On an idle VM, Activity Monitor is the second-busiest thing on the machine at 3.5% CPU and 23 threads, beaten only by the compositor (screenshot). It doesn't so much observe the system as join it.
- The battery menu sends you here to see "apps using significant energy" (`src/menus/status-menu.ts:82`, `src/menus/start.tsx:208`). You arrive and there's no Energy tab (`apps/activity-monitor/menus.ts:14-19`), nothing is selected, and you're looking at `systemd-userdbd`.
- Two rows both say `mirin-metal-host` and one says `bun` (screenshot). Every Dashi app shows up as the renderer or the runtime, so the one question this app exists for, "which app is that?", has no answer. Meanwhile the parent pid is read on every tick (`read.ts:116`) and then dropped (`sample.ts:44-62`).
- The title bar carries "Activity Monitor / All Processes" on two lines. Right next to it is a popup that also says "All Processes" (screenshot; `view.tsx:147`, `view.tsx:201`). That's the name twice and the filter twice, inside a window whose app name is already in the menu bar.
- In the % CPU column, four rows show exactly `0.5` (screenshot). That's one 10 ms clock tick over 2 s, printed with a decimal place it hasn't earned (`sample.ts:47`, `monitor.ts:12`).
- The stop-sign button, the popup, the segmented tabs and the red/green "CPU LOAD" strip with `System:` / `User:` / `Idle:` all come from macOS's Activity Monitor, and the code says so: "as on the Mac" (`summary.tsx:2`, `format.ts:5`, `format.ts:23`). The brand rule is "inspired, not imitated".

**Improvements**

1. **Recommended.** *What:* Make apps the default rows. Walk ppid to the process that owns a window (lift `ownerOf` from `src/battery/apps.ts` into a shared module), show the app's icon and name, fold helpers and renderers under a disclosure, and keep a View → "All Processes (flat)" / "Process Tree" switch for experts. Add `ppid` to `ProcessRow`. *Why:* Today `mirin-metal-host` ×2 and `bun` are unidentifiable (finding 2), and quitting the right thing is the app's main job. *Size:* M (needs window → pid from the shell over IPC; inferred).
2. **Recommended.** *What:* Add an Energy tab driven by the same model as the battery menu (cores kept busy, averaged), and let the battery menu open Activity Monitor with that app selected (`launchApp(id, { select: key })`). *Why:* It closes a dead end the system itself sends people into (finding 1). *Size:* M.
3. **Recommended.** *What:* Make sampling cheap and move it off the UI thread. Read /proc in a Bun Worker. Use one `stat` read plus `fstat` of `/proc/<pid>` for the uid instead of parsing `status`, except on the Memory tab. Skip kernel threads unless they're shown. Pause while the window is hidden or minimized (needs a kit visibility signal). Count sockets every few ticks. Offer View → Update Frequency (1 s / 2 s / 5 s / Paused). *Why:* The observer shouldn't be the second-biggest load (finding 4), and sync I/O on the render thread will stutter on busy machines. *Size:* M.
4. **Recommended.** *What:* Fix the numbers in one pass. Memory = `RssAnon + RssShmem` (same file). Show per-process CPU smoothed over about 3 samples, and as whole numbers below 1%. Label the column "% of one core" in its tooltip. Show steal separately or leave it out. Exclude kernel threads from "Threads". Disk columns become bytes per second (keep totals as a secondary column). Ignore `veth`/`docker`/`virbr`/`tun`/`wg` interfaces in network totals. *Why:* An activity monitor that's wrong is worse than none (findings 6–11). *Size:* S–M.
5. **Recommended.** *What:* Bring the toolbar down to one row. Drop the subtitle and the in-window title (the menu bar already names the app), and give the stop button a text label "Quit…". Disable it, with a reason in a tooltip, for rows that can't be quit. *Why:* It follows the owner's chrome rule and frees about 150 px for the search field (findings 5, 19). *Size:* S.
6. *What:* Make quitting safe and complete. Return in search selects the first match; it no longer opens the sheet. Before signalling, re-read `/proc/<pid>/stat` and compare `starttime` (or use a pidfd). After SIGTERM, watch for about 3 s and offer "“X” is still running. Force quit it?". Fix Activity Monitor's own refusal text ("Use ❖Q to quit Activity Monitor."). Offer "Quit as administrator…" for other users' processes via polkit. *Why:* Findings 3, 12, 13 and the refusal in `policy.ts:16`. *Size:* M.
7. *What:* Do a copy pass. Use sentence case for columns and figures ("Process", "CPU time", "Memory used", "Swap used"). Graph titles become "CPU load", "Memory used", "Disk activity", "Network activity". Remove the colons. Sheet: "Quit “Notes”?" / "Notes will close. Force quit ends it immediately, and anything unsaved is lost." Menu: "Quit Process…". Empty state: "No matches". *Why:* Brand voice (finding 15). *Size:* S.
8. *What:* Add an Inspect sheet on double-click and Return, and a right-click menu (Quit…, Force Quit…, Inspect, Copy PID, Copy command line, Show in Files). Turn on multi-select via `selectedKeys`. *Why:* These are day-one basics (finding 17). *Size:* M.
9. *What:* Search should also match the command line and a partial user, and use the placeholder "Search processes". Keep the selected row in view, and hold the sort steady for a moment while the pointer is over the table. *Why:* Findings 16 and 18. *Size:* S.
10. *What:* Add a GPU column and tab from `/proc/<pid>/fdinfo/*` `drm-engine-*` counters (amdgpu/i915/xe), so the renderer's real cost shows up. *Why:* Every Dashi app draws through a GPU host; its cost is invisible today. *Size:* L.
11. *What:* Let the summary strip collapse (View → Show Summary), show a scale label on autoscaled graphs ("2 MB/s"), and put each value right after its label. *Why:* Vertical space, and unreadable graphs (finding 20). *Size:* S.

**One big idea**

Make the window answer "what is slowing, heating or draining my computer, and can I stop it?" rather than dump a pid table. Use one app-first list where each row is an app (icon, name, window count) with a single combined impact meter for CPU, memory, energy and GPU, and helpers folded in. Use the same model the battery menu and Force Quit already half-share, so all three surfaces agree on what an app is and what it costs. The summary strip says it in one plain line ("Files is using most of your processor") with Quit… beside it. The pid table stays one View menu choice away for people who want it. That's the place to go past "inspired by the Mac": no desktop OS today connects the battery menu, Force Quit and the monitor into one coherent "who is costing me" story.

**Cross-app notes**

- `AppWindow`'s `subtitle` prop (`dashi-ui/src/window.tsx:39`, `106-108`) invites two-line titles everywhere, which breaks the owner's rule. Remove it, or render it inline after the title ("Activity Monitor — All processes") in the same row.
- `ToolbarButton` has no tooltip or accessible name (`window.tsx:141-151`). Every icon-only toolbar button in every app is a guessing game. Add a required `help` string.
- `Table` (`dashi-ui/src/table.tsx`) has no keyboard navigation of its own, no scroll-into-view for the selection, no double-click/activate callback, and no column resize or reorder. Selected ink is hard-coded `#ffffff` (`table.tsx:118`). Apps work around this through search fields (`view.tsx:160`).
- There are no chart or series tokens, so apps either invent colors (`summary.tsx:17` `#3b82c4`) or reuse semantic ones (`critical`, `selection`) and break "one color, one job". Add a small series palette (2–4 hues, light and dark) to `theme/palette.ts` and document it in `docs/design.html`.
- `Sheet` maps Enter to `onConfirm` unconditionally (`sheet.tsx:43`). For destructive or irreversible sheets the design system should say which button is the default and that it's never the destructive one. The default also shouldn't be reachable from an Enter that began in another field.
- The kit gives apps no visibility or occlusion signal (`apps/kit/` has none), so every polling app (this one, and likely others) burns CPU while minimized.
- "As on the Mac" in code comments (`dashi-ui/src/table.tsx:2`, `summary.tsx:2`, `format.ts:5`) is a symptom. Shared components and copy are drifting toward imitation, against `docs/brand.html`'s "inspired, not imitated".
- Copy rule enforcement: column headers, figure labels and empty-state titles across `@dashi/ui` consumers mix Title Case and sentence case. A lint or test over the visible strings would catch this.
- Process identity ("which app is this pid?") is computed in `src/battery/apps.ts`, again in `src/force-quit/model.ts`, and not at all here. It belongs in one shared module.
