# Portal dialogs and dashi-dialog

There is no screenshot for these. Everything below comes from reading `packages/shell/apps/portal/` and `packages/shell/apps/dialog/`.

**The roast**

- The file chooser lets you walk into a folder but never back out. There is no Up, no Back and no path bar, so Places is the only exit, like a hotel whose only fire exit is in the lobby (`file-chooser/view.tsx:164-233`).
- Click a file you already selected and the dialog opens it. Slow double-clickers get a surprise ending (`file-chooser/view.tsx:217-220`).
- The print sheet's Copies field won't let you delete the "1". Clear the field and it snaps straight back (`print/sheet.tsx:60-63`).
- "You can change this later in Settings › Privacy." Settings has no Privacy pane (`access.tsx:89`; `settings-app/panes/`).
- `dashi-dialog` is a faithful Zenity clone, down to "Add a new entry" and "Calendar selection". The exception is `--file-selection`, the mode scripts use most, which exits 255 (`dialog/spec.ts:106`).
- Every dialog spends its one chrome row on a title that the next line repeats: "Add to Dock", then "Add “YNAB” to the Dock?" (`dynamic-launcher.tsx:135,150`).

**Improvements**

1. **Recommended.** *Give the file chooser real navigation.* Put a folder pop-up (the current folder, which opens its parents) beside the search field in the one toolbar row. Add Back with ❖[ and Up with ❖↑. Typing "/" or "~" opens a go-to-folder field. Use the same sidebar as Files: favorites, drives, network. *Why:* finding 1 traps people. Today the only way out of a subfolder is to start over from Places. *Size:* M.
2. **Recommended.** *Real double-click and Enter.* Open on a double-click within the system interval, or on Enter. A single click only ever selects. Shift and Ctrl extend the selection when `multiple` is set. *Why:* finding 2 makes the chooser accept files people only meant to look at. *Size:* S.
3. **Recommended.** *Fix the print sheet.* Copies becomes a Stepper that accepts an empty field while typing and checks the value on blur. Esc and Enter work from every field. Printers and paper become PopUpButtons. Show a first-page thumbnail, and say why Print is disabled ("Pages 12–15 don’t exist; this document has 9."). *Why:* findings 3, 4, 11 and 16. Print is the dialog people use under time pressure. *Size:* M.
4. **Recommended.** *Make access decisions reviewable and harder to grant by accident.* Add a Privacy & security pane that lists the permission store's grants per app, with Remove; point the fallback copy at it. Ignore Enter for the first 500 ms of an Access sheet, or make Allow click-only. *Why:* findings 5 and 6. Consent you can't see or undo isn't really consent. *Size:* M.
5. **Recommended.** *Support `dashi-dialog --file-selection` through the chooser.* Reuse `ChooserView` in the dialog process (`--save`, `--directory`, `--multiple`, `--filename`, `--file-filter`). Then do `--color-selection`, and honor `--icon` from the icon theme. *Why:* finding 7. It is the Zenity mode scripts use most, and the UI already exists. *Size:* M.
6. *Drop the title row from sheets.* When a portal dialog hangs from a window, draw it as a `@dashi/ui` Sheet-style card where the question is the title, with no toolbar. A dialog with no parent keeps a slim drag strip. Merge `PortalFrame` and `DialogFrame` into one `@dashi/ui` `AlertWindow`. *Why:* finding 9, and the two frames are near copies of each other and of `ConfirmSheet`. *Size:* M.
7. *A copy pass.* Show the MIME description ("Always use for PDF documents"), "Default app" in muted text, "Save as" with no colon, one disclosure pattern ("Show more options" / "Show fewer options"), and sentence-case buttons ("Don’t allow"). Zenity's empty default titles become the calling program's name, read from the parent process (a proposal). *Why:* finding 10. *Size:* S.
8. *Make replace a real question.* Use `ConfirmSheet` with an ume button: "“report.pdf” already exists in Documents. Replacing it overwrites what’s in it." *Why:* finding 13. *Size:* S.
9. *Chooser basics.* Add Show hidden files (⇧❖.), New Folder (⇧❖N) when saving, Files' per-type icons and a list/grid switch, a Size column, and dates that follow Region settings. *Why:* finding 14. *Size:* M.
10. *Use the shared pieces.* Use one Checkbox and a `@dashi/ui` MonthGrid that follows Region settings, with left and right moving by a day once `onKeyDown` is in. Drive the pulsing bar with a native animation, or show a static striped bar under Reduce Motion. *Why:* findings 15, 17 and 19. *Size:* S.

**One big idea**

One chooser everywhere. Make the file chooser Files-in-a-sheet and a `@dashi/ui` component: Files' sidebar, Files' list and icon views, and Files' omnibox in the single toolbar row (type a path or search there), with Space for a preview and drag-in from Files. Then every place that picks a file uses it. That includes the portal and `dashi-dialog --file-selection`, and also Dashi’s own apps. Text Editor's Open and Save As is a typed path because "the portal’s would be another app’s window" (`apps/editor/sheets.tsx:1-5`). Calendar falls back to a typed "/home/you/Downloads/holidays.ics" when no chooser is around (`apps/calendar/sheets.tsx:142-143`). If Dashi's own apps won't use the chooser, no other app's developer will trust it.

**Cross-app notes (for `@dashi/ui` and the guidelines)**

- **Picking a file is a library component, not an app feature.** First-party apps must never ask for a typed path when the chooser exists. (Text Editor does today; Calendar does in a development run.)
- **One alert frame.** `PortalFrame`, `DialogFrame` and `ConfirmSheet` become one `@dashi/ui` component with the same icon tile, title, message and button row, and the same Esc and Enter rules. A sheet has no title row: its first line is the question.
- **Default buttons follow the risk.** Enter presses the button that goes ahead only when going ahead is safe and reversible. For grants, deletions and replacements, the default is the safe answer or click-only, and the destructive button is ume.
- **A list of unknown length is never pills.** Printers, filters, paper sizes and apps use a PopUpButton or a list.
- **Dates, weekdays and the clock come from Region settings,** through one helper (`src/region/week.ts`), in every process the portal and dialog included.
- **Disclosure has one pattern and one wording:** a chevron and "Show more …" / "Show fewer …", in ink, not in kombu link text.
- **Copy points only at panes that exist.** A string that names a Settings pane should come from the pane registry, so a rename or a missing pane fails a test.
- **Every animation checks Reduce Motion,** and nothing animates by re-rendering React on a timer.
