# Files

Paths are relative to `packages/shell/` unless they start with `dashi-ui/` (`packages/dashi-ui/`) or `mirin-metal/` (`../mirin/packages/mirin-metal/`).

**The roast**

- Files has a "Select" toggle in its toolbar, the check-in-a-circle button in files.png, because shift-click and ❖-click never reached the desktop. Turn it on, forget about it, and double-clicking a folder stops opening it, in every folder you visit after that (`apps/files/toolbar.tsx:55-69`, `store.ts:311-318`).
- In icon view, Left and Right do nothing. Up and Down move a whole row, so you can't reach the file next to the selected one from the keyboard unless you type its name (`apps/files/view.tsx:163-184`, `dashi-ui/src/key-sink.tsx:41`).
- Files never overwrites anything, and it never asks either. Drag in a newer `report.txt` and you get `report 2.txt`, then `report 3.txt`, until you're sure you're losing your mind (`ops.ts:4-6`, `paths.ts:72-81`).
- There's no Undo. Trash something by mistake and the footer says "Moved “x” to the Trash.", then disappears five seconds later (`operations.ts:190`, `store.ts:459`).
- files.png mixes two icon families in one folder. `build.log` gets the theme's striped page, while `install.err`, `install.events` and `build.done` (plain text logs) get a blank page with an empty rounded square on it, which tells you nothing (`icons/other.svg`, `mime.ts:1-6`).
- The field says "Search, or type a path". Click it, though, and it fills in `~/` and asks where you'd like to go (`omnibox.tsx:93`, `omnibox.tsx:41-45`).

**Improvements**

1. **Recommended.** *What:* Move Files' keyboard to Metal's `onKeyDown` (and upgrade `KeySink` to it for every app). Make the arrows move in two dimensions in the grid, Shift+arrow extend the selection, Home/End jump, Space peek, ❖⌫ Move to Trash, F2 rename, ❖↓ open, and Delete/⇧❖⌫ act in the Trash. *Why:* the icon view can't be driven from the keyboard today, and most of the missing basics in this report depend on it. *Size:* M.
2. **Recommended.** *What:* Bring in real desktop selection. Add modifiers to `onPress` in mirin (or follow the modifier state from `onKeyDown`). Shift-click selects a range, ❖-click toggles, and a rubber band (`onPointer` on the background) selects an area. Clicking empty space deselects. Retire the Select toggle, or keep it only for touch screens. *Why:* the mode button is a touch pattern on a desktop, and it quietly breaks double-click. *Size:* M (L with the mirin change).
3. **Recommended.** *What:* Keep an undo history of every write (rename, move, copy, trash, new folder, put back), with Edit ▸ Undo ❖Z / Redo ⇧❖Z and an "Undo" button in the footer notice. *Why:* moving files around without undo makes people work carefully and slowly, and a trash done by mistake has no quick way back. *Size:* M.
4. **Recommended.** *What:* Add a conflict sheet: "“report.txt” already exists in Documents." showing both files' date and size, with Replace / Keep Both / Skip, "Apply to all", and Merge for folders. Keep the NOREPLACE machinery, which already does the work safely; just ask first. Use the same sheet in the file chooser. *Why:* silent "name 2" files make the person tidy up afterwards, and replacing a file is impossible today. *Size:* M.
5. **Recommended.** *What:* Space opens a peek overlay inside the window, reusing Preview's renderers (images, PDF, text, audio and video). The arrow keys step through the selection, Space or Esc closes it, and an "Open in…" button sits at its edge. *Why:* it's the fastest way to see what's in a file, and Files has none. *Size:* L.
6. *What:* Rename in place on the tile or row label: F2, or a second click on a selected name after a pause. Select the stem without its extension, Enter commits, Esc cancels. Keep the sheet only for search results. *Why:* a modal sheet is too heavy for the most common edit. *Size:* M.
7. *What:* Show a magnifier at the start of the field. A click there means search, with empty text. Typing `/` or `~` switches to a path, and ❖L or ⇧❖G opens the path editor. Turn the scope chip into a two-option `Choices` ("Home | Everywhere"). *Why:* search is invisible today, and a click lands in path mode. *Size:* S.
8. *What:* Draw one Dashi file-icon family: a neutral page that follows light and dark mode, with a category glyph, special-folder emblems that match the sidebar glyphs, and the extension as a small label on unknown types. For files with an unknown extension, sniff the first 512 bytes in the background so text files read as "Text document". *Why:* the screenshot's grid has no single visual language, and unknown files say nothing. *Size:* M.
9. *What:* Remember view, sort (with direction) and Show Hidden, globally with per-folder overrides, plus the window size. Add "Reverse order" to the sort menus. *Why:* setting the view again every launch makes Files feel stateless. *Size:* S.
10. *What:* New Folder creates "untitled folder N" right away using `freeName`, selects it, and starts the inline rename. No sheet. *Why:* fixes the second-folder failure and saves a dialog. *Size:* S.
11. *What:* Keep the old listing up until the new one lands, and show "Loading…" only after about 200 ms. *Why:* removes the flicker on every navigation. *Size:* S.
12. *What:* Give `MenuItem` separators and shortcuts. Group the item menu (Open, Open With / Get Info, Rename, Duplicate / Copy, Cut, Paste / Compress / Move to Trash). Use the same "Move to Trash" label everywhere, write "View as Icons", and ship zip/bsdtar so "(needs zip)" and the "Install zip or bsdtar" copy go away. *Why:* menus should be easy to scan, and the labels shouldn't talk about packages. *Size:* S.
13. *What:* Progress should show an animated indeterminate bar while the total is unknown, then "12 of 340 files · 1.2 of 4 GB · about 2 minutes left". Start copying while the size is still being measured. *Why:* a bar frozen at 35% looks broken. *Size:* M.
14. *What:* Crumbs collapse from the left into "…" (which opens a menu of the hidden folders). Hide the status line when the field is tight and show it on hover instead. *Why:* the current folder's name matters more than "70.4 GB available". *Size:* S.
15. *What:* Memoize `visible()` per snapshot. Look thumbnails up asynchronously and cache them by path and mtime. Watch `/proc/self/mountinfo` (POLLPRI) and udisks instead of polling `lsblk`. Debounce path completions and make them async. Apply watcher events as diffs instead of reloading. *Why:* large folders and network mounts are where this code will freeze first. *Size:* M.
16. *What:* List every mounted disk's Trash (or at least count it). Say so honestly in the Empty Trash sheet, and show an empty or full glyph on the Trash sidebar row. *Why:* deletions shouldn't be invisible. *Size:* S/M.
17. *What:* Let people edit Favorites by dragging a folder in, choosing Remove from Sidebar, and reordering. Build the sidebar on an extended `SidebarItem` with drop and trailing-action props. Use neutral glyph ink. *Why:* everyone's top folders are different, and the fork drifts from the kit. *Size:* M.
18. *What:* Add ❖N New Window in the same process, Extract for archives, Open in Terminal, Copy Path (⌥❖C), resizable list columns, and a collapsible sidebar (View ▸ Hide Sidebar). Skip tabs unless they fit in the one toolbar row. *Why:* people expect these on day one, and none of them needs a second bar. *Size:* M.

**One big idea**

One file browser, used everywhere. Extract Files' core (store, grid and list, sidebar, omnibox, peek, conflict sheet, icons) into a shared component, and have the portal file chooser embed it as a sheet with an Open/Save footer. Every "Open…" in every app would then be Files: the same sidebar with drives and your favorites, thumbnails, crumbs, type-to-select, Space to peek, the same search and the same Replace question. Each fix above would land in both places at once. In an OS where most file work goes through other apps' Open and Save dialogs, that would feel more best-in-class than any single feature.

**Cross-app notes**

- `KeySink`/`keys.ts` describe a Metal that no longer exists. `onKeyDown` delivers every key with its modifiers (`mirin-metal/src/types.ts:168-176`, `:268`), but every app on `KeySink` still lacks Left/Right, Space, Delete, Tab and modifiers (`dashi-ui/src/keys.ts:1-17`, `key-sink.tsx:41`). Rebuild `KeySink` on `onKeyDown` and widen `KeyInput`.
- `onPress` has no modifiers (`mirin-metal/src/types.ts:245`), so no list in Dashi can do Shift- or ❖-click. That needs fixing in the platform, not in each app.
- `PopupMenu`/`MenuItem` have no separators, submenus, keyboard navigation or disabled-reason (`dashi-ui/src/sheet.tsx:114-185`), so every context menu in Dashi is a flat list. Add `{ type: "separator" }` as the menu-bar specs already have (`apps/files/appmenus.ts:15`).
- `SidebarItem`'s doc says a bare glyph is "in the text's color", but the code tints it kombu (`dashi-ui/src/sidebar.tsx:16-17` vs `:45`). Under "one color, one job", sidebar glyphs should be ink or muted, with kombu only for the selected row. It also needs `onDrop` and a trailing action so apps like Files stop forking it.
- `Table` needs resizable and hideable columns (`dashi-ui/src/table.tsx:52-55`). Any list-heavy app hits this.
- Fields: the omnibox paints its field with `colors.button` while `@dashi/ui` has `surface.field` (`apps/files/omnibox.tsx:70`; `dashi-ui/src/theme/surface.ts:22-23`). Pick one token for "a field", or hover states and fields will look the same in dark mode.
- Dates and sizes are formatted twice, in Files' `format.ts:39-55` and the chooser's `view.tsx:19-25`. Put `formatDate` and `formatSize` in a shared module so "Today at 11:19" reads the same everywhere.
- Loading states: make "show Loading only after ~200 ms, keep stale content until then" a design rule and build it into `EmptyState`.
- Undo and conflicts are patterns, not app features. Add both to the design guidelines: every destructive or moving action offers ❖Z and a notice with Undo, and a name collision is always a Replace / Keep Both / Skip sheet.
- The design guide's Icons section covers app icons only. Add a document and folder icon recipe (page shape, category glyph, light and dark, whether extension text is allowed) so Files, the chooser and Preview draw the same files.
- Menu-bar shortcuts in `docs/design.html` ("Move to Trash… ❖⌫") aren't used by the app the example comes from. Keep a single list of standard shortcuts that the apps read from.
