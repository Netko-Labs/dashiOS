# Text Editor

**The roast**

- It's a text editor where you can't click in the text or select a word. The Edit menu offers "Copy All", which is what you ship when Copy didn't make it.
- Press ❖S and the caret jumps somewhere new. Saving remounts the text input, so every save is also a small game of "where was I?".
- Closing a document asks "Do you want to save the changes…?" when you pick File → Close, and asks nothing when you press ❖W. One close path is polite and the other just quietly writes to a recovery folder.
- Every window is called "Text Editor". Open five documents and the Window menu has five rows, each saying "Text Editor".
- Save is drawn as a download arrow, Open as a path you type from memory, and the footer's "UTF-8 · LF" assumes everyone is a developer.
- Find tells you "3 of 12 · line 40" and then leaves you to find line 40 yourself, since nothing is highlighted.

**Improvements**

1. **Recommended.** *What:* Give mirin a real document view (or extend `TextInput`) with caret offset and selection range in and out, pointer placement, drag and ⇧ selection, Cut and Copy, find-match highlighting, line-level virtualization, and a gutter slot. Then make Edit → Cut/Copy standard and drop Copy All. *Why:* Everything else on this list sits on top of selection (#1, #9, #10, #11). Today the Editor can't do what a 1990s Notepad did. *Size:* L.
2. **Recommended.** *What:* Stop remounting the input. Take `focus` out of the `TextInput` key, add an imperative focus (or a `focusToken` prop the host honors without remounting), and keep the caret and scroll across Save, sheets and Undo. *Why:* The caret jumping on ❖S is a constant small betrayal (#2). *Size:* S.
3. **Recommended.** *What:* Use one close path that never loses work. Put ❖W on File → Close (the shell already routes ❖W to the app first, `shortcuts.ts:119-122`) so ❖W asks. Write recovery continuously, debounced about 2 s after typing stops, not only at exit. When a file with kept changes is opened directly, offer "Restore unsaved changes from 10:42?" in place. *Why:* #3 and #4. Calm means not losing anything and not nagging. *Size:* M.
4. **Recommended.** *What:* Show the document's name on one line. Call `host.setTitle(name)` so the Window menu, switcher and taskbar name documents. Drop the subtitle, and show the folder as a muted suffix on the same line, or in the title's menu or hover. Replace " — Edited" with an edited mark on the close control (see Cross-app). *Why:* #6, #7, #16. *Size:* S (title) / M (edited mark).
5. **Recommended.** *What:* Make Revert safe. Ask first ("Revert “notes.txt” to the last saved version? Your recent changes will be lost."), or better, keep it undoable by recording the revert as one history step instead of `history.clear()`. *Why:* #5. *Size:* S.
6. *What:* Remove the footer. Put counts in View → Show Word Count (shown in the title row's muted text when on). Move encoding and line endings to File → Reopen with Encoding and to options in Save As. Show notices as a transient line in the toolbar's title area. *Why:* #7, and the footer mostly shows "0 lines · 0 words · 0 characters" (`editor.png`). *Size:* M.
7. *What:* Add a real file chooser: a shared `@dashi/ui` file sheet with places, recent files, folder browsing and type-ahead, keeping the typed path as a fallback. Also accept files dropped on the window (mirin `onDrop` exists, `../mirin` commit 74aeade). *Why:* #8. *Size:* L (sheet) / S (drop).
8. *What:* Cut per-keystroke cost. Compute stats lazily (debounced, or only when shown). Make `isDirty` a flag set from history plus a saved revision counter. Debounce Find recounts. Drop the hidden full-text mirror once the input reports its content height. *Why:* #10. Then raise the 4 MB cap. *Size:* M.
9. *What:* Watch the file (`fs.watch` plus an mtime check before writing). Reload quietly when the document is clean, and ask when it's dirty ("“notes.txt” changed on disk. Keep your version or use the one on disk?"). *Why:* #12. *Size:* S/M.
10. *What:* Fix encodings. Fall back to Windows-1252 (a superset for practical purposes), add Reopen with Encoding, and let Save As choose the encoding and line endings. Keep mixed endings unless the person converts them. *Why:* #13. *Size:* S.
11. *What:* A compact find row in the toolbar's place, not a sheet: Find and Replace fields, Replace, Replace All, Match Case and Whole Word toggles. ❖G and ⇧❖G keep working. *Why:* #14. It also keeps the one-row rule while replacing. *Size:* M.
12. *What:* Code-friendly basics behind View: Line Numbers, Wrap Lines, Go to Line… (❖L), tab width and spaces, auto-indent, and later syntax coloring for the types `EDITOR_MIME_TYPES` claims. *Why:* #15. *Size:* M (L with syntax).
13. *What:* Redraw Save as a document with a check, or a page with a down arrow into it, distinct from Download. Label the toolbar buttons once tooltips exist. Disable Save on an untouched Untitled. *Why:* #17. *Size:* S.

**One big idea**

Replace the single `TextInput` with a real document surface, a mirin editor view backed by a rope or piece table. It would have line virtualization, a real caret and selection API, multi-caret, inline find highlights, a gutter (line numbers, change marks since the last save) and continuous versioned autosave. With that, the Editor stops apologizing ("Copy All", typed paths, the caret jumping on save) and gains a calm, Dashi-shaped promise: **you never lose a word, and you never get asked.** Close a window and it reopens exactly where you were, caret and scroll included. File → Revert To browses earlier versions. Large files open instantly. The same surface would also serve Notes, the Terminal's find field, and every code-ish text field in the OS.

**Cross-app notes**

- **`AppWindow`'s `subtitle` prop produces two-line titles** (`dashi-ui/src/window.tsx:104-110`), and design.html still documents "subtitle 11" for the unified toolbar. That contradicts the owner's one-row rule. Either remove `subtitle` or render it inline and muted on the title's line.
- **`AppWindow`'s `footer` prop is a second bar by design** ("A strip under the content", `window.tsx:49-50`). The guidelines should say whether footers are ever allowed (Activity Monitor's graphs?) and default to no.
- **Apps don't retitle their windows.** The kit could sync `AppWindow`'s `title` to `host.setTitle` automatically, so every document app names its windows in the Window menu, switcher and taskbar (`src/menus/model.ts:197`).
- **There's no "edited" concept in the system.** Add a compositor/IPC window flag (`set-edited`), drawn as a Shapes-consistent change to the close control (the ume circle drawn as a ring, say), and mirrored in the Window menu and Dock. Then apps stop appending " — Edited".
- **mirin gaps that block document apps:** no selection or caret API on `TextInput` (`types.ts:291-307`), and a controlled `value` that resets the native buffer (`types.ts:292`). There's no way to hold a window open to ask on close (`tasks/todo.md:366`), no tooltips (`tasks/todo.md:374`), and no clipboard API.
- **The `reservedBy` test contradicts the shell.** `reserved.ts` refuses ❖W in app menus, but `shortcuts.ts:119-122` hands ❖W to the app's row first, which is how Terminal's Close Tab works. That's why the Editor's Close has no ❖W and closes without asking. Make the rule say "❖W is the app's if it has a row, else the window's", and test it that way.
- **There's no shared file chooser in `@dashi/ui`.** Every app that opens or saves (Editor, Preview, Notes export) will reinvent the typed-path sheet. One file sheet component should exist.
- **The error color isn't ume.** `palette.ts:71` sets `critical: "#d4483b"`, while brand.html says ume (#D0596F) is "Closing and destroying: … errors". The Editor's footer errors use `critical`. Decide which one errors use, and make the tokens match.

**Where it stands (0.5.0)**

Wave 1 gave the Editor mirin's text model and a close that asks; wave 2 (`feat/0.5-editor`) gave it the big idea's promise, "you never lose a word, and you never get asked", on mirin's `TextInput` (the pick in `docs/0.5.0.html`) rather than a new document view.

- [x] 2. The caret stays put through Save, sheets and Esc (wave 1), and now through Undo and Replace All too: the window holds the caret and selection (`text-area.tsx`, controlled `selection`).
- [x] 3. One close path, and it never asks: a file saves on its own a moment after typing stops and as the window goes, however it goes; an Untitled document is kept as a draft (`main.tsx`, `model.ts` `autosave`).

- [x] 5. Revert is safe: File › Revert To… lists the file's earlier versions (as opened, each ❖S, and one every ten minutes of autosaving, thinned by age) and reverting is one Undo step (`versions.ts`, `sheets.tsx` `VersionsSheet`).
